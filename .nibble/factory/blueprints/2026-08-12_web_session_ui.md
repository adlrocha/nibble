# Blueprint: Web Session Inspector (`nibble web`)

## Summary

Add a background web service to nibble that serves a dark-mode browser UI for
inspecting pi agent sessions (`~/.pi/agent/sessions/**/*.jsonl`): a usage
dashboard (tokens, cost, models, activity heatmap), a searchable session
browser, a full conversation viewer (text, thinking, tool calls, tool
results), and live nibble task state from the SQLite DB. Installed and
auto-started by `install.sh` as a systemd user service, reachable from other
Tailscale devices.

Inspired by github.com/Dwsy/pi-session-manager, but implemented as a
`nibble web` subcommand in the existing Rust binary (reuses parsing patterns
from `usage/pi_log.rs`, no separate runtime).

## Scope

- In: session scan/parse/summarize, stats aggregation, HTTP JSON API,
  embedded single-page dark UI, token auth, systemd unit, install/uninstall.
- Out: session resume/hand-off, tags/kanban, editing, multi-agent sources
  (Claude Code logs etc.), WebSocket live tail, markdown rendering deps.
- Dependencies: `tiny_http` (new, sync HTTP server), existing serde/chrono/rusqlite.

## What's Changing

- `Cargo.toml`: add `tiny_http` dep; add `env` feature to clap.
- `src/cli/mod.rs`: new `Commands::Web { host, port, token }`.
- `src/main.rs`: `mod web;` + dispatch `Commands::Web` → `web::serve(...)`.
- `src/web/mod.rs`: server bootstrap, auth, routing, index cache.
- `src/web/sessions.rs`: JSONL discovery/parsing → summaries + detail events (pure functions, injectable root dir).
- `src/web/stats.rs`: aggregation over summaries (per-model, per-day, per-project, totals).
- `src/web/index.html`: embedded dark-mode SPA (vanilla JS, no external assets).
- `install.sh`: stop-on-upgrade + `nibble-web.service` (systemd user),
  token generation into `~/.nibble/web.env`, print access URL.
- `uninstall.sh`: remove service + env file.
- `docs/web.md`, `README.md`: document the feature.

## Data Types

- `WebConfig { host: String (default "0.0.0.0"), port: u16 (default 7878),
  token: Option<String> (env NIBBLE_WEB_TOKEN), sessions_root: PathBuf,
  db_path: PathBuf }`
- `SessionSummary { id, file_path, cwd, project, title (first user msg, 120
  chars), started_at, last_active_at, message_count, user_message_count,
  models: Vec<String>, input_tokens, output_tokens, cache_read_tokens,
  cache_write_tokens, cost_usd: f64, size_bytes }`
- `SessionDetail { summary fields + events: Vec<SessionEvent> }`
- `SessionEvent = User{text} | Assistant{text, thinking, tool_calls: Vec<ToolCall>,
  model, usage} | ToolResult{tool_name, text, is_error} | ModelChange{provider, model}`
- `Overview { totals…, per_model: Vec<ModelStat>, per_day: Vec<DayStat>,
  per_project: Vec<ProjectStat>, running_tasks: Vec<TaskInfo> }`

## Interfaces

| Name | Input | Output | Errors |
|------|-------|--------|--------|
| `web::serve(cfg)` | `WebConfig` | `Result<()>` (blocks) | bind failure → anyhow error |
| `summarize_file(path)` | `&Path` | `Option<SessionSummary>` | unreadable/corrupt → None (skip) |
| `parse_detail(path)` | `&Path` | `Option<SessionDetail>` | missing file → None → 404 |
| `scan_index(root)` | `&Path` | `Vec<SessionSummary>` | unreadable dir → empty vec |
| `build_overview(summaries, db)` | slices + `Option<&Database>` | `Overview` | DB open failure → empty tasks, never fatal |
| `GET /` | — | index.html | — |
| `GET /api/overview` | — | `Overview` JSON | 401 if bad token |
| `GET /api/sessions?q=&project=` | query params | `[SessionSummary]` JSON | 401 |
| `GET /api/session/{id}` | session UUID | `SessionDetail` JSON | 404 unknown id |
| `GET /api/session/{id}/raw` | session UUID | raw JSONL download | 404 |

## State Machine / Flow

1. `serve()` binds TcpListener via tiny_http → per-request worker threads.
2. Auth gate: if `token` set, require `?token=` or `Authorization: Bearer`.
3. API handlers read a `Mutex<IndexCache>`: TTL 3s; rebuild = walk sessions
   root, per-file cache keyed `(path, mtime, len)`; stale entries evicted.
4. Detail/raw requests resolve id → path via the same index (no client-
  supplied paths ever touch the filesystem).

## Events / Side Effects

- Reads: session JSONL files, nibble SQLite DB (read-only, best-effort).
- Writes: none at runtime. install.sh writes unit file + `~/.nibble/web.env`.
- Logs: startup line with bind addr + access URL to stdout/journald.

## Constraints

- Bind `0.0.0.0` by default (Tailscale reachability); token auth generated by
  install.sh to cover hostile-LAN exposure. `--host 127.0.0.1` to lock down.
- Read-only: no endpoint mutates session files, DB, or anything else.
- No client-controlled filesystem access (INV-3).
- UI: dark mode, self-contained (no CDN/fonts), usable on phone browsers.
- Large files: raw endpoint streams from disk; detail parse is on-demand only.

## Invariants

1. (INV-1) Corrupt/partial JSONL lines are skipped, never fatal to a scan.
2. (INV-2) No endpoint writes to disk or DB (read-only service).
3. (INV-3) Filesystem access only via session-id → index lookup; request
   paths/params are never joined into filesystem paths.
4. (INV-4) With a token configured, every route (incl. `/`) returns 401
   without valid credentials.
5. (INV-5) Summary token totals equal the sum of per-assistant-message usage
   fields for well-formed files.
6. (INV-6) Index rebuilds preserve id → path uniqueness (first wins on
   collision; ids are UUIDs so collisions indicate corruption).

## Acceptance Criteria

1. (AC-1) Given a sessions root with valid JSONL files, `GET /api/sessions`
   returns one summary per file with correct title, cwd, counts, token sums.
2. (AC-2) Given a valid session id, `GET /api/session/{id}` returns events in
   file order with user/assistant/toolResult/model_change entries.
3. (AC-3) Given `?q=foo`, only sessions whose title or message text contains
   "foo" (case-insensitive) are returned.
4. (AC-4) With `NIBBLE_WEB_TOKEN=secret`, unauthenticated requests → 401;
   `?token=secret` → 200.
5. (AC-5) `GET /api/session/<unknown>` and traversal attempts → 404.
6. (AC-6) `install.sh` installs + starts `nibble-web.service`; port serves UI.
